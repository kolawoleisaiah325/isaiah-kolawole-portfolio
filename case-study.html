01 / THE PROBLEM

Which reports need attention?

Programme teams need to know whether a low service figure reflects a reporting gap, an invalid submission, or a valid count. Combining those cases can lead to the wrong follow-up.

The project asks a focused question: which fictional facilities need attention because their reports are missing, invalid, or below an operational target?

The Streamlit dashboard reads the processed CSV outputs, so it can run without a database server. This website’s interactive demo presents those same versioned records in the browser.

A missing or invalid report keeps its delivered count unknown. A submitted zero stays zero. Resubmissions remain in the audit log, with a clear selection decision.

04 / THE AI ASSISTANT

A draft with an evidence trail.

The reporting module builds a structured evidence pack, then uses a local Ollama model to draft qualitative statements. Verified numbers and source references are added by the program.

  • Rejects unknown citations and model-authored numbers.
  • Checks for malformed outputs and selected unsupported causal claims.
  • Records a deterministic fallback if the local model is unavailable.
  • Keeps the brief as a draft requiring human review.

The browser demo does not run the LLM. It lets visitors inspect the data and measured evaluation behind the project.

05 / THE LIMITATIONS

What I would validate next.

The same holdout selected and evaluated the model, so the reported error may be optimistic. The illustrative forecast band is a descriptive error range, not a calibrated prediction interval.

A next iteration would reserve an independent test period, evaluate stability across facilities, and examine stock and supply constraints. Delivered doses do not establish unique patients, vaccination coverage, true demand, or health outcomes.

For real data, the first step would be agreeing indicator definitions and data use authority, reconciling a sample to source records, and testing the workflow prospectively with programme staff.
